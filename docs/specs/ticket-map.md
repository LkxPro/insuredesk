## Problem Statement

工单没有地址信息，运营/管理无法看到投诉、退费等工单在全国的地域分布，也无法按地区定位工单。全库目前不存在任何省市区/地址字段，前端也没有地图能力。

## Solution

1. 所有种类的工单新增可选的「地址」：省 / 市 / 区县三级，手动从级联下拉中选择（可输入文字搜索），不含详细地址文本。
2. 新增独立页面「工单地图」：白底、只画省界的全国地图，每张已填地址的工单在其区县位置显示一个统一大小的红点，同一区县的多个红点错开排布；支持筛选、缩放、悬浮提示，点击红点跳转工单列表按该区县过滤。
3. 新增权限点 `ticket_map.view` 控制地图页可见。

## User Stories

1. 作为坐席，新建或编辑任一种类工单时，我可以选填工单地址（省→市→区县），下拉可输入文字搜索。
2. 作为坐席，我可以清空已填的地址。
3. 作为坐席，我只能提交「不填」或「选到最后一级」的地址；未选到最后一级时无法提交并提示。
4. 作为查看工单的人，我在工单详情页看到地址（「广东省 深圳市 南山区」，直辖市为「北京市 朝阳区」），未填写时显示为空占位。
5. 作为工单列表用户，列表不新增地址列。
6. 作为持有 `ticket_map.view` 的用户，侧边栏出现「工单地图」入口，打开即看到当前筛选下的全部红点；没有该权限看不到入口，直接访问路由返回 403。
7. 作为地图用户，我看到白底全国地图，只有省界，含南海诸岛小框。
8. 作为地图用户，每张已填地址的工单是一个红点，红点大小统一；同一区县多张工单的红点在区县中心周围错开，不完全重叠；放大地图后点更分散。
9. 作为地图用户，我可以滚轮缩放、拖拽平移，并一键复位视图。
10. 作为地图用户，鼠标悬浮红点显示「省 市 区县：N 例」，N 为该区县在当前筛选下的工单数。
11. 作为地图用户，鼠标悬浮省份板块显示「省名：N 例」，N 为该省当前筛选下已定位的工单数；省份板块高亮。
12. 作为地图用户，我可以按创建时间范围、用户反馈渠道（多选）筛选；创建时间默认近 90 天，可选「全部」；改变筛选后地图重新查询绘制。
13. 作为地图用户，每次打开地图页都实时查询最新数据，不读缓存。
14. 作为地图用户，我在地图页看到「已定位 N 例」统计；未填地址的工单不显示在地图上，也不单独统计。
15a. 作为地图用户，我双击省份进入单省视图：只显示该省及其市界（直辖市/港澳为区界），悬浮市显示「市名：N 例」，可「返回全国」。
15b. 作为地图用户，我可以用右上角开关显示/隐藏地名：全国视图为省简称（不标港澳），单省视图为市名（直辖市/港澳为区名）。
15c. 作为地图用户，每个红点都落在其所属区县（市级叶子为市）的边界内，不越界。
15. 作为同时持有 `ticket.view` 的地图用户，点击红点跳转到工单列表，列表按该区县 + 地图当前筛选条件过滤，且条数与悬浮提示的 N 一致；列表上显示可移除的「地区：xx区」筛选标签。
16. 作为没有 `ticket.view_all` 的用户，地图只统计我可见的工单（与工单列表数据范围一致）。
17. 作为管理员，我可以在角色管理里给角色勾选「工单地图」权限。
18. 作为开放分析 API 消费方，工单接口返回地址字段（省/市/区县的区划码与名称）。
19. 作为导出工单的用户，导出文件包含省、市、区县三列。
20. 作为查看操作日志的人，地址变更出现在工单处理记录中。

## Implementation Decisions

### 数据模型

- `tickets` 核心表新增 6 个可空列：`province_code`、`province_name`、`city_code`、`city_name`、`district_code`、`district_name`。放核心表而非投诉侧表，因为所有种类都可填。
- 区划码为 6 位国家行政区划代码字符串。
- `province_code`、`city_code`、`district_code` 各建单列索引；按定位码过滤写成 `district_code = X OR (district_code IS NULL AND city_code = X) OR (district_code IS NULL AND city_code IS NULL AND province_code = X)`，不依赖表达式索引。
- 不新建表，ETL publication 与 etl_ro 授权无需改动。

### 地址不变式

- 级联树层级按 DataV 原样，不补虚拟层级。已核实 DataV 存在三种非标准形态：
  - 直辖市（京津沪渝）与港澳：省 → 区县两级，无市级；
  - 无下辖区县的市及省直辖县级单位（东莞、中山、儋州、嘉峪关、济源、海南省直辖县市等）：省 → 市两级，市为叶子；
  - 台湾：仅省级，省为叶子。
- 地址要么全空，要么为级联树中从省到某个叶子节点的完整路径；各级码按节点 level 写入对应列（直辖市地址的 city 列为空）。其他组合一律拒绝。
- 服务端校验区划码存在且上下级关系正确；名称由服务端根据区划码从区划数据回填，不信任客户端传来的名称。
- 「定位码」= 叶子节点码，即 `district_code ?? city_code ?? province_code`。地图与列表过滤均按定位码。
- 区划数据随版本更新后，已存工单的码可能在新数据中不存在：详情页照常显示已存名称；地图上该类工单无法取得坐标，不画点，不报错。

### 区划数据

- 来源：阿里 DataV.GeoAtlas 的行政区划边界数据。开发时一次性下载并转换，产物提交进仓库，随前端/shared 打包，运行时（浏览器与服务端）零外网请求，内网/离线环境可用。本次不提供可重跑的更新脚本。
- 从同一份源数据转换出以下静态资源（gzip 后合计目标 ≤ 300KB）：
  1. 省市区级联树（码 + 名称，约 3200 条），shared 包内，前后端共用（前端选项、后端校验与名称回填）；前端在打开工单表单时懒加载；
  2. 定位码 → 经纬度中心点表（取 DataV 叶子节点要素自带的 `center`），地图页懒加载；
  3. 简化后的全国省界 GeoJSON（含南海诸岛/九段线），地图页懒加载，体积目标 ≤ 200KB。
- 三份资源同源转换，区划码一致；由 unit 测试守护一致性（见 Testing Decisions）。构建时不联网。

### 输入与编辑

- shared 的工单创建、`editComplaint`、`editRefund` 入参新增可选 `address`（仅码），复用同一校验。
- 编辑协议：不传 `address` = 保留原值且不校验原值；`address: null` = 清空；传对象 = 校验后整体替换。已存失效区划码不阻止编辑其他字段。
- 模块边界：完整区划树只在独立模块中，shared 主入口、web 首屏与 web 表单 schema 不静态引用；表单只校验选到叶子，完整路径校验由服务端负责。
- 地址只出现在详情标签、导出（省/市/区县三列）、操作日志标签。`TICKET_FIELD_DESCRIPTORS` 目前派生导入表头（`TICKET_IMPORT_HEADERS`）、导入列、导入模板、建单必填字段清单与外部账号视图，地址不进入建单必填字段清单与外部账号视图；导入不在本次范围，不做要求。
- 外部账号建单表单（`ticket.create_external`）不加地址字段。

### 地图接口

- 新 router `ticketMap`，过程 `points`，需 `ticket_map.view`。
- 入参：创建时间范围（复用 `createdRangeFields`）、`userFeedbackChannelId`（多选，空选为不过滤）；语义复用工单列表筛选（`ticket-filter.ts` 与列表 where 构建），保证与列表下钻条数一致；`source` 采用列表默认值（排除 `file_import`）。
- 数据范围与工单列表一致：无 `ticket.view_all` 只统计分配给本人或本人创建的工单；排除软删除工单；排除未填地址工单。
- 出参：按定位码分组的 `{ code, provinceCode, provinceName, cityName, districtName, count }[]`。不返回单张工单明细。省份计数与「已定位」总数由前端按有坐标的定位码汇总；无坐标的定位码（历史失效码）不画点，也不计入省份与总数。
- 每次请求实时查询，前端不设置 staleTime 缓存，页面挂载即刷新。

### 地图页

- 路由 `/ticket-map`，侧边栏「工单地图」，权限 `ticket_map.view`；地图占满内容区。
- 渲染：ECharts（按需引入 geo + scatter + tooltip），仅地图页懒加载。不使用在线瓦片或地图服务商。
- 底图：省份白色填充、灰色省界，悬浮省份高亮并显示该省计数；开启缩放与平移，限定最小/最大缩放。
- 红点：统一大小的红色圆点。前端按每个定位码的 count 在其中心点周围生成 count 个点，用向日葵螺旋（第 i 点半径 ∝ √i，角度递增 137.5°）排布；间距以经纬度为单位，单个区县的点设最大半径，数量多时整体压缩间距以保持在最大半径内。排布由 count 确定性计算，同一数据每次渲染位置一致。
- 悬浮红点显示「省 市 区县：N 例」；红点悬浮优先于省份悬浮。
- 点击红点：有 `ticket.view` 时跳转 `/tickets?locationCode=<定位码>&<当前地图筛选>`；无 `ticket.view` 时不可点击。
- 性能验收：开发环境用 2 万点模拟数据实测缩放/平移、悬浮、点击均正常；ECharts large 模式若导致悬浮或点击失效则不得使用。

### 工单列表

- `ticketListInputSchema`（及导出入参）新增 `locationCode` 过滤（匹配定位码 `district_code ?? city_code ?? province_code`）与 `userFeedbackChannelId` 多选过滤。
- 两个参数的 URL 序列化/反序列化与现有多选筛选参数机制一致。
- 列表页读取 URL 中的 `locationCode`，显示可移除的「地区：<名称>」筛选标签；`userFeedbackChannelId` 只经 URL 生效，前端不显示任何对应控件或标签。不新增地区/用户反馈渠道筛选下拉，不新增地址列。

### 权限

- `packages/shared/src/permissions.ts` 新增 `ticket_map.view` 与标签「工单地图」；进入角色管理 checklist；管理员自动拥有；不给其他种子角色默认授予。

### 详情页

- 投诉类与退费类详情页都展示地址（只读展示 + 编辑表单内可编辑）。

### 开放分析 API

- 工单响应新增 `province_code/name`、`city_code/name`、`district_code/name`（非 `complaint_` 前缀，属核心字段）；同步更新响应 zod 与 `/docs/analytics` 字段说明。

## Testing Decisions

- shared unit：地址校验——全空通过；省/市/区县三级通过；直辖市省/区县两级通过；无下级市省/市两级通过；台湾仅省通过；未到叶子、上下级不匹配、不存在的码均拒绝。
- 区划数据一致性 unit 测试（进 `make check`）：级联树 34 个省级单位齐全；每个定位码都在中心点表中且坐标落在中国经纬度范围内；省码与省界 GeoJSON 的省份一一对应；GeoJSON 含南海诸岛要素；东莞、中山、儋州、嘉峪关、济源在树中为市级叶子；京津沪渝港澳下直接为区县；台湾为省级叶子；北京朝阳区与长春朝阳区码不同且各自可选。
- 手工验收：断网环境下打开工单表单与地图页，省市区下拉与地图均正常显示，浏览器网络面板无外部域名请求。
- api integration：
  - 创建/编辑写入地址后名称由服务端回填，忽略客户端名称；清空地址生效；操作日志记录地址变更。
  - `ticketMap.points`：按定位码与省分组计数正确；排除软删除、未填地址、默认排除 `file_import`；创建时间/用户反馈渠道筛选生效；无 `ticket.view_all` 只统计本人可见；无 `ticket_map.view` 拒绝。
  - 列表 `locationCode` + `userFeedbackChannelId` 过滤结果条数与 `points` 同条件下该码的 count 一致（覆盖三级、直辖市两级、市级叶子、省级叶子四种形态）。
  - 开放 API 返回地址字段；导出含省市区列；导入模板不含地址列。
- web unit：螺旋排布函数确定性、点数等于 count、全部落在最大半径内、点间不重合；地址级联表单的提交校验；地图页无权限不出导航入口；点击跳转 URL 携带定位码与筛选参数。
- 测试位按仓库惯例：`apps/api/src/**` colocate unit，`apps/api/test/**` integration，新 router 两套测试位齐全。

## Out of Scope

- 详细地址文本、门牌号，以及任何地理编码（地址文本→经纬度）。
- 按渠道（如「内部客服热线」）限制或强制填写地址；地址对所有工单一律选填。
- Excel 导入地址；历史工单地址回填。
- 工单列表地址列、列表地区筛选下拉（仅支持地图下钻带来的 `locationCode`）。
- 外部账号建单表单的地址字段。
- 区划数据的更新脚本与年度更新机制。
- 工单列表的用户反馈渠道筛选控件或标签（仅保留 URL 参数）。
- 地图上展示单张工单信息、热力图、按数量缩放点大小、按省份着色深浅。
- 看板页嵌入地图。
- 地图数据缓存或预聚合。

## Further Notes

- 「客服热线」在系统中无对应渠道值（最接近的是用户反馈渠道/接收渠道字典中的「内部客服热线」）；因地址对全部工单开放，本 spec 不依赖该判定。
- 中国地图须保留南海诸岛与九段线；本页面仅限内部使用，对外公开展示需审图号。
- DataV 数据的使用条款需在落地前确认；区划代码每年有调整，本次不做更新机制，需要时另开任务；已存工单的名称不受影响。
- 地图筛选只有创建时间与用户反馈渠道；列表原本不支持按用户反馈渠道过滤，为保证下钻条数一致而补该过滤参数。
- 本 spec 不涉及 ETL 文档改动（仅加列，`docs/etl-database-access.md` §7 已声明 schema 无兼容承诺）。
