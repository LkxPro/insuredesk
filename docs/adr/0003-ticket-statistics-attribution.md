# ADR 0003: 工单统计归属于当前责任人

## 状态

已接受

## 上下文

数据看板需要统计每个客服的工单数据（进单数、完单数、超时数）。当工单被改派时，需要决定统计归属逻辑。

**方案 A：按当前责任人统计**
- 工单的所有统计数据归属于当前的 assigneeId
- 改派后，原责任人不再计入该工单
- 优点：统计简单，直接按 assigneeId 分组
- 缺点：改派后原责任人的工作量不可见

**方案 B：按处理历史统计**
- 统计时分析 ProcessLog，所有处理过该工单的人都计入
- 原责任人计"参与数"，最终责任人计"完单数"
- 优点：更全面反映每个人的贡献
- 缺点：统计逻辑复杂，需要定义多种计数规则

**方案 C：快照式统计**
- 改派时，将原责任人的统计数据"冻结"（如进单 +1）
- 新责任人继续累计后续统计（如完单 +1）
- 优点：保留历史贡献
- 缺点：同一工单被多人统计，总数对不上

## 决策

采用**方案 A**：按当前责任人统计。

**统计规则**：
```sql
-- 跟进人统计
SELECT 
  assigneeId,
  COUNT(*) as total_tickets,
  COUNT(*) FILTER (WHERE status = 'completed') as completed_tickets,
  COUNT(*) FILTER (WHERE now > dueAt AND status != 'completed') as overdue_tickets
FROM tickets
WHERE assigneeId IS NOT NULL
GROUP BY assigneeId
```

## 理由

1. **清晰的责任归属**：数据看板展示的是"谁当前负责哪些工单"，而非历史参与记录
2. **避免重复计数**：确保所有工单统计数之和等于工单总数
3. **实现简单**：直接基于 assigneeId 分组，无需复杂的日志分析
4. **业务合理性**：完单数、超时数等指标应归属于最终完成/导致超时的责任人

## 影响

- 改派工单后，原责任人的工作量在当前统计中不可见
- 如需评估个人历史贡献，应通过 ProcessLog 单独统计（如"参与处理的工单数"）
- 主管在改派时应考虑到统计归属的变化
- 可以在个人工作台增加"历史参与工单"视图，基于 ProcessLog 查询
