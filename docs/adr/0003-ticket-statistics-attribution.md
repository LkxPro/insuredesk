# ADR 0003: 客服考核统计归属于当前责任人

**状态**:已接受

跟进人考核表 3 个维度全部按**当前 assigneeId** 归属,不追踪转单历史、不统计转单数:

- **完单数**:assigneeId = 该客服 且 status = completed
- **平均完结时长**:completionTime − createdAt 的平均值(端到端口径,与 SLA 时钟统一)
- **超时单数/超时率**:名下曾经超时的工单——含超时完结(completionTime > dueAt)与在途超时(未完结且 now > dueAt)

工单完结后 assigneeId 不再变化,"完结人"即"完结时的责任人",归属永久冻结;各人统计之和等于工单总数,无重复无遗漏。软删工单一律排除。

拒绝的方案:按 ProcessLog 分析历史经手人(支持转单数维度)——统计逻辑复杂,且同一工单多人计数,总数对不上;转走且未完结的工单本就不算业绩产出,改派过程在 ProcessLog 时间线可查。

**两个超时口径有意不同,不是矛盾**:

- 考核"超时单数" = 历史追责视角:曾超时就计入,含超时完结
- 看板"已超时数" = 实时运营视角:仅在途且已过 dueAt,完结即移出

特急投诉无 dueAt,永不计入任何超时口径。

已知取舍:

- 端到端时效含派单延迟与改派前前任持有时长,衡量"进系统到解决的总时长"而非个人速度,横向对比不完全公平;若未来需要个人真实时长,新增 lastAssignedAt 改用 completionTime − lastAssignedAt。
- 不追踪转单历史 = "超时那一刻的持有人"担责,理论上存在甩单漏洞;缓解:dueAt 不重置(ADR 0002)+ 改派留痕,争议以 ProcessLog 为准。
