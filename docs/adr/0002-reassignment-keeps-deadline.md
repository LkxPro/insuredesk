# ADR 0002: 改派工单时处理时限不重置

## 状态

已接受

## 上下文

当工单从一个客服改派给另一个客服时，需要决定 dueAt（处理时限）如何处理。

**方案 A：重新计算 dueAt**
- 改派时，从改派时间重新计算时限（如：改派时间 + 3天）
- 优点：对新接手的客服更公平，有足够时间处理
- 缺点：可能导致工单被多次改派以延长时限，客户等待时间过长

**方案 B：保持 dueAt 不变**
- 改派时，dueAt 保持首次分配时计算的值
- 优点：确保客户诉求在固定时限内得到响应，避免通过改派拖延
- 缺点：新接手的客服可能面临紧迫的 deadline

## 决策

采用**方案 B**：dueAt 锚定在工单**录入时刻 createdAt**，创建时一次算定，此后（含分配、改派）永不重算。

**工单创建时**：
```
dueAt = createdAt + duration(complaintLevel)   // 由投诉等级决定；特急投诉不设 dueAt
```

**分配 / 改派工单**：
```
assigneeId = newUserId
dueAt = 保持不变（createdAt 不变，dueAt 天然稳定）
```

> 说明：早期版本曾将 dueAt 锚定在 assignedAt（首次分配时刻）。后修正为锚定 createdAt——因为 SLA 是对客户的承诺，客户不关心内部何时分配，只关心从提交起算的总时长。修正后"改派不重置"从一条需要主动维护的规则，变成了 createdAt 不可变带来的自然结果。

## 理由

1. **客户优先**：时限承诺从客户提交（录入）起算，不因内部分配/改派而延长
2. **防止滥用**：无法通过反复改派规避超时责任
3. **未分配也计时**：工单一旦录入即开始倒计时，倒逼尽快分配，避免烂在未分配池
4. **实现简单**：dueAt 恒等于 createdAt + 时长，无需在多个分配入口维护"是否首次"的判断

## 影响

- 主管在改派工单时，需要查看剩余时间，避免将即将超时的工单分配给新客服
- 系统应在改派时显示剩余时间提醒
- dueAt 由投诉等级（complaintLevel）决定，与 priority 无关（priority 是独立自由标签，见 PRD §3.1.5、§9.2）
- 新接手的客服可能收到已经超时或即将超时的工单，需要在通知中明确标注
