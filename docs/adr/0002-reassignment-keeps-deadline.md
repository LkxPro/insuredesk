# ADR 0002: 改派工单时处理时限不重置

## 状态

已接受

## 上下文

当工单从一个客服改派给另一个客服时，需要决定 dueAt（处理时限）如何处理。

**方案 A：重新计算 dueAt**
- 改派时，从改派时间重新计算时限（如：改派时间 + 3天）
- 优点：对新接手的客服更公平，有足够时间处理
- 缺点：可能导致工单被多次改派以延长时限，客户等待时间过长

**方案 B：保持 dueAt 不变**
- 改派时，dueAt 保持首次分配时计算的值
- 优点：确保客户诉求在固定时限内得到响应，避免通过改派拖延
- 缺点：新接手的客服可能面临紧迫的 deadline

## 决策

采用**方案 B**：改派时 dueAt 保持不变。

**首次分配**：
```
assignedAt = now
dueAt = assignedAt + duration(priority)
```

**改派工单**：
```
assigneeId = newUserId
dueAt = 保持不变
```

## 理由

1. **客户优先**：工单的时限承诺是对客户的，不应因内部改派而延长
2. **防止滥用**：避免通过多次改派来规避超时责任
3. **激励快速响应**：促使主管在改派时考虑剩余时间，选择合适的接手人
4. **统计准确性**：如果改派重置时限，很难准确评估团队的实际响应速度

## 影响

- 主管在改派工单时，需要查看剩余时间，避免将即将超时的工单分配给新客服
- 系统应在改派时显示剩余时间提醒
- 如果确实需要延长时限（如客户同意延期），应该通过"调整优先级"或"延期"功能，而不是改派
- 新接手的客服可能收到已经超时或即将超时的工单，需要在通知中明确标注
