# ADR 0010: 迁移 append-only,schema 变更须带数据回填

**状态**:已接受(作废 ADR 0009 的"迁移约定翻转"计划)

系统已部署生产环境,存量数据必须保留。迁移约定自此固定:

- **append-only**:迁移只增不改——已有迁移文件不改写、不删除、不
  squash。生产库 `_prisma_migrations` 记录着已应用文件的校验和,改写
  会使 `migrate deploy` 校验失败,或让变更在已部署库上漏放。
- **schema 变更须带数据回填**:影响存量数据的变更(非空新列、列拆并、
  枚举收窄等)必须在迁移 SQL 中携带回填/转换语句,保证 `migrate deploy`
  跑完后存量数据完整可用;不再假设"重建库即可"。
- 开发库不受限:本地 `docker compose down -v` 重建随意,约定只约束迁移
  文件本身。

ADR 0009 把 append-only 的生效点定在首个 release tag,此前保留"可改写
历史迁移 / squash 成基线"的余地。该余地作废:生产已部署,本约定即时
生效,不再以 release tag 为界。

拒绝的方案:

- **维护 down 迁移**——沿用 ADR 0009 的只前滚结论,理由不变。
- **用备份恢复代替回填**——备份是灾难兜底(会丢备份之后的数据),不是
  常规升级路径;升级不应以丢数据为代价。
