# ADR 0005: SLA 采用可配置的类型化规则引擎

**状态**:已接受

业务硬性要求**管理员可修改 SLA 规则**(不硬编码),且各等级规则形态异构(检查点 2~3 个不等、特急独有滚动提醒)。采用 SLAPolicy(按投诉等级各一条)+ 类型化 `reminderRules[]`,2 种 type:`follow_up_checkpoint`(跟进检查点)/ `rolling_follow_up`(滚动提醒,特急专用)。字段与各级默认值见 PRD §3.8。

拒绝的方案:硬编码 + 少量可配数值(改规则要发版,不满足硬性需求);固定列配置表(检查点数量不定造成空列,滚动提醒塞不进,无法新增类型)。

要点:

- **首响独立于规则列表**:firstResponseMinutes 是 SLAPolicy 主体字段,仅作"待首响"染红阈值,不是一条提醒规则。
- 规则作为"我的待办"的**读时谓词**运行(见 ADR 0004),无发送/幂等/去重概念。
- 时钟起点一律 createdAt(滚动提醒以上一条 comment 为基准);跟进次数 = 累计 comment 数,跨责任人累加;completed 后掉出待办。
- 管理员改规则、或改工单 complaintLevel(dueAt 按新等级立即重算),都只影响**之后的读时判定**——已错过的检查点天然不满足进入条件,无需"跳过不补发"特判。

代价:需要 SLAPolicy 存储 + 管理员配置界面,是本期较重的一块。
